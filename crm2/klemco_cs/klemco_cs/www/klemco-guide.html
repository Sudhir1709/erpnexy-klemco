Sales Order — Field Guide

What every field on a Sales Order is for — in plain terms. The Details tab is the order itself; the More Info tab holds the Klemco workflow fields plus optional ERPNext extras.

Rule of thumb

A normal order needs only: Company (Klemco India), Customer, the Items, a Delivery Date, and the source Warehouse. Tax now fills in by itself. Unsure about a field marked System-set or Optional? Leave it — it won't hold up the order.

  • You fill you enter or attach it
  • System-set filled automatically — read only
  • Optional only if you use that feature

Details

The order form

The main tab — who's buying, what, from where, and for how much.

Order header

Who the order is for and its key dates.

CompanyYou fill

Which Klemco legal entity is selling. Use "Klemco India" — it holds the GSTIN, so tax auto-applies. ("Klemco India (Demo)" has no GSTIN and won't auto-tax.)

SeriesSystem-set

The order-number format (e.g. SAL-ORD-YYYY-#####). Auto-assigned on save.

CustomerYou fill

Who's buying. Picking the customer pulls their price list, addresses, tax info and the Klemco Rate-Contract flag.

Order TypeOptional

ERPNext's own classification — Sales / Maintenance / Shopping Cart. Leave on Sales for a normal order. (This is different from the Klemco "Order Type" on More Info, which is One-Shot vs Phased.)

DateSystem-set

The order date — defaults to today; editable.

Delivery DateYou fill

When the customer expects the goods. Can't be back-dated (Klemco rule FR-SO-16).

Tax IdSystem-set

The customer's GSTIN — pulled from their record.

Skip Delivery NoteOptional

Tick for orders with no physical shipment (e.g. services), so the order doesn't wait on a Delivery Note. Leave unticked for goods.

Accounting Dimensions

Tag the order for financial reporting.

Cost CenterSystem-set

The cost centre the revenue is booked against — usually defaults from the company.

ProjectOptional

Link the order to a Project to track revenue/cost against it. You can create a new Project inline from here (CS roles can now do this). Leave blank if it's not project work.

Currency & Price List

The pricing basis for the order.

Currency / Exchange RateSystem-set

Order currency (INR) and its conversion rate — set from the customer / price list.

Price ListYou fill

Which price list supplies the item rates. Defaults from the customer; change it to switch the whole order to a different price list.

Items & Warehouse

The products being sold and where they ship from.

Items tableYou fill

The heart of the order — each line: Item Code, Delivery Date, Quantity, and Rate. Add rows with Add row / Add multiple, or via Get Items From (pull from a Quotation).

Scan BarcodeOptional

Add items by scanning a barcode instead of typing the code.

Set Source WarehouseYou fill

The warehouse the goods ship from. Setting it here applies it to every item row at once. It drives the stock check, reservation, the Delivery Note source, and the Klemco low-stock / backorder warning. For a finished-goods sale, pick Finished Goods.

Reserve StockOptional

Earmark on-hand stock for this order so it can't be committed elsewhere (needs stock reservation enabled). Leave off for normal orders.

Taxes

The GST applied to the order — now determined automatically.

Tax CategorySystem-set

In-State (CGST+SGST) vs Out-State (IGST) — now auto-picked from the plant state (the company GSTIN) vs the customer's delivery state. You no longer choose it by hand; override only for a special case.

Sales Taxes and Charges TemplateSystem-set

The actual GST template applied (e.g. Output GST In-state / Out-state) — filled automatically from the Tax Category. The rows below it show the CGST/SGST/IGST lines.

Shipping RuleOptional

Auto-adds a freight/handling charge based on a predefined rule. Leave blank if you don't charge freight on the order.

Incoterm / Named PlaceOptional

International delivery terms (EXW, FOB, CIF…) and the place they apply. For exports only — leave blank for domestic orders.

Totals & Discount

The order value — computed by the system — plus an optional order-level discount.

Total / Net Total / Grand TotalSystem-set

Item total, total taxes, and the final Grand Total (with Rounded Total and In Words). All calculated — nothing to type.

Advance PaidSystem-set

Any advance received against the order, from linked Payment Entries.

Additional DiscountOptional

An order-level discount (a % or amount) applied on the Net Total or Grand Total, plus an optional Coupon Code. Note: line-item discounts are blocked for Rate-Contract customers (BR-SO-01).

Flow

Working with orders

How documents connect, and the everyday tasks around them.

The document flow

Each document is created from the one before it — you don't retype anything.

The chainOrder → Cash

Quotation → Sales Order → Delivery Note → Sales Invoice (payment follows). A quotation becomes an order; the order is dispatched on a Delivery Note; the invoice bills for it. Klemco requires each Sales Invoice to come from a Sales Order.

Submit firstKey rule

You can only build the next document from a submitted one — a Delivery Note or Invoice can't be made from a draft Sales Order. Fill the order, then Submit it (discount approval / credit hold, if any, must clear first).

Create a Delivery Note from an order

Always start from the submitted Sales Order — not a blank Delivery Note.

StepsYou do

1. Open the Sales Order and Submit it.  2. Click Create → Delivery Note (top-right), or the Save & Create Delivery Note button.  3. The Delivery Note opens pre-filled with the order's items — set the Source Warehouse (one that has stock) → Submit.

Can't see the option?Why

The order is probably still a Draft (submit it first), or it's already been fully delivered (nothing left). A blank New Delivery Note from the list won't link to the order unless you use Get Items From → Sales Order — so start from the order instead.

See a document's linked documents

Trace the whole flow from any document.

Connections tabBuilt in

Open any document → the Connections tab (in the tab bar). It shows every linked document up and down the chain — Quotation, Sales Order, Delivery Note, Sales Invoice, Payment — with counts. Click any to jump. The document's timeline on the right also lists them.

Who created an order, and when

The list already carries this — just surface it.

Sort & columnsList view

The list is sorted by Created On (the “2 M / 1 M” = time since creation; hover for the exact date). To show them as columns, use the list's ⚙ (gear) → Pick Columns and add Created On and Created By. (These are system fields, so the choice saves per user; ask your admin for a shared saved view if the whole team should see them by default.)

Warehouse dispatch — Docket, Tracking, POD

These are captured on the Delivery Note (the warehouse's document), because they're known at dispatch — after the order is submitted and locked.

WhereDelivery Note

Open the Delivery Note → Dispatch & Tracking section → Docket / LR #, Tracking URL, Proof of Delivery (POD). These stay editable even after the Delivery Note is submitted, so the warehouse can add the POD once the goods are delivered.

WhoWarehouse

The Stock User / Stock Manager role (who creates the Delivery Note) fills these. Mandate docs — Customer PO Copy, Test Certificates, Client Order Confirmation — are provided earlier by CS / Sales on the Sales Order before confirmation.

Adding freight (and other charges)

Freight is a charge line, not a field — added when the amount is known (after dispatch).

HowYou add

On the Sales Invoice (billed after delivery) → Taxes table → Add row → Type: Actual, Account Head: “Freight and Forwarding Charges”, Amount: the freight cost. It's added to the invoice total. (You can add the same line on the Delivery Note if you prefer to record it at dispatch.)

WhenAfter the Challan

Freight is known once the Delivery Challan is raised and the transporter confirms the cost — so it's normally entered at billing time on the invoice. For automatic freight (by value or weight) an admin can set up a Shipping Rule.

Sharing a document with a specific person

Give one person access to one record — on top of their role permissions.

Share buttonRight sidebar

On any document, the Share action (right sidebar) lets you grant a specific user access to this one record — even if their role wouldn't normally show it. Useful for looping someone in (e.g. an escalated complaint to the Inventory Head).

The checkboxesAccess levels

Read = view · Write = edit · Submit = submit · Share = re-share to others. The “Everyone” row shares with all users. Sharing adds access; it never removes what a role already grants.

Built for Klemco

The Customer-Service workflow — order type, approvals, credit & dispatch documents.

Customer Service

Sets how the order is fulfilled and flags special customer terms.

Order TypeYou fill

One-Shot = the whole order ships in one delivery. Open (Phased Delivery) = staggered delivery against a plan, where each line can carry its own required date. Pick One-Shot for a normal order.

Rate Contract CustomerSystem-set

Pulled from the Customer master. When ticked, discounts are blocked on every line. You don't set it here — it comes from the customer. BR-SO-01

Order Execution

Instructions and transporter preference passed to the warehouse and dispatch.

Delivery InstructionsYou fill

Special handling — unloading requirements, delivery time windows, safety notes. Printed on the Delivery Challan for the warehouse and transporter.

Preferred 3PL PartnerOptional

The courier to use — Mahindra Logistics, DTDC, Blue Dart, Delhivery, EcomExpress, FedEx India, or Other. A routing hint for dispatch.

Discount Approval

Tracks whether an extra discount needed sign-off. Mostly filled by the approval workflow.

Discount Approval StatusSystem-set

Not Required · Discount Approval — Sales Head · Approved · Rejected. Set automatically from the discount given versus the threshold.

Approved By / TimestampSystem-set

Who approved the extra discount, and when.

Discount Threshold (%)You fill

The limit above which an order needs Sales Head approval. A line discount over this % routes the order for sign-off before it can proceed. BR-OE-01

Approval / Rejection RemarksOptional

Notes the approver leaves when approving or rejecting.

Credit Control

Shows whether the order is blocked for credit reasons. Maintained by the credit check — read only.

Credit Hold StatusSystem-set

Clear or On Hold. An order goes on hold when the customer breaches their credit terms; Finance must release it.

Hold ReasonSystem-set

Why the order is on credit hold.

Released BySystem-set

The Finance user who cleared the hold.

Mandate Documents

Compliance documents that must accompany the order.

Customer PO CopyYou fill

Scanned or digital purchase order from the customer. Some customers require it before the order can proceed. BR-SO-02

Test CertificatesYou fill

Quality / test certificates for the goods. Supports multiple files or a ZIP.

Client Order Confirmation

The customer's SKU-mapping document, uploaded on the order before confirmation.

Client Order ConfirmationCS / Sales

A Word document (.docx / .doc only) supplied by the customer that maps their internal SKUs to Klemco SKUs — the warehouse needs it during packing. On save it is auto-attached to the linked Delivery Note. FR-SO-15 · BR-SO-08

Docket / LR, Tracking, PODOn the Delivery Note

These are now captured by the warehouse on the Delivery Note (Dispatch & Tracking section) — not here — because they're known at dispatch, after the order is submitted. See Warehouse dispatch below.

Standard ERPNext

Stock features that ship with ERPNext. Most are optional — set them only if you use them.

Status

Progress indicators ERPNext maintains automatically as the order is delivered and billed. Nothing to fill here.

StatusSystem-set

Where the order is in its lifecycle — Draft → To Deliver and Bill → Completed → Closed / Cancelled.

% DeliveredSystem-set

How much of the ordered quantity has shipped, via Delivery Notes.

% Amount BilledSystem-set

How much of the order value has been invoiced, via Sales Invoices.

% PickedSystem-set

How much has been picked in the warehouse, via Pick Lists — if you use picking.

Commission

Use only if an external agent / sales partner earns a commission on this order.

Sales PartnerOptional

The external agent, broker, or dealer for this deal.

Commission Rate / TotalOptional

The % and the resulting amount payable to that partner. Leave the whole section blank if there's no external partner.

Sales Team

Split internal credit or incentive across your own salespeople — for reporting.

Sales TeamOptional

Add rows of Sales Person + contribution % (must total 100%). Leave empty if you don't track per-salesperson attribution.

Auto Repeat

Turn this into a recurring order that ERPNext re-creates on a schedule. For standing / subscription orders only.

From / To DateOptional

The active window for the recurrence.

Auto RepeatOptional

Links to the schedule (daily / weekly / monthly…) that regenerates the order. Ignore for one-off orders.

Print Settings

Cosmetic controls for the printed PDF — they don't change the order data. Defaults are usually fine.

Letter HeadOptional

Which company letterhead appears on the printout.

Print HeadingOptional

An alternate title for the printed document.

Print LanguageOptional

Language of the printout.

Group same itemsOptional

Merge duplicate item rows on the print.

UTM Analytics

Marketing attribution — which campaign produced this order. Relevant only if you track campaigns in the CRM.

Source / Medium / Campaign / ContentOptional

The marketing channel or campaign the order can be traced back to. Otherwise leave blank.

Additional Info

Miscellaneous references.

Customer's Purchase Order / DateYou fill

The customer's PO number and date. (Klemco also captures the actual PO file under Mandate Documents → Customer PO Copy.)

Internal / Inter-company fieldsSystem-set

Is Internal Customer, Represents Company, Inter Company Order Reference — used only for inter-company orders (one group company selling to another). Ignore for external customers.

Billing

The warehouse on a Sales Invoice

Why billing shows no warehouse — and how to get it when you need it.

A Sales Invoice shows no warehouse by default — on purpose.

Normal flowVia Delivery Note

Order → Delivery Note (dispatch — you pick the warehouse there) → Sales Invoice (billing). Stock already moved on the Delivery Note, so the invoice just bills for what shipped — no warehouse needed.

Direct billingTick Update Stock

Billing without a Delivery Note? Tick Update Stock on the invoice — the Set Source Warehouse field then appears (pre-filled with the company's Finished Goods warehouse). Pick where stock comes from; billing reduces it. Don't use it when a Delivery Note already moved the stock — ERPNext hides the option once items come from a DN, to avoid deducting twice.

Setup

Email automation

The backend account the system sends all automated mail from.

Configured and verified with a live test send — automated CS email now goes out from a single default outgoing account.

AccountConfigured

Email Account “Klemcotest” — klemcotest@gmail.com
SMTP smtp.gmail.com : 587 (TLS) · Outgoing ✓ · Default Outgoing ✓ · Incoming off (not needed for sending).

What sends through itAutomatic

Complaint logged · Order acknowledgement · Dispatch notification · Credit-hold alerts. Every Klemco CS notification uses whichever account is marked Default Outgoing.

Change sender or passwordAdmin

Search → Email Account → Klemcotest → edit the email address or password → Save. ERPNext tests the SMTP connection on save and stores the password encrypted — a wrong password fails immediately with an auth error.

Gmail App PasswordIf needed

If Google ever rejects the plain password, generate a 16-character App Password (myaccount.google.com → Security → 2-Step Verification → App passwords → Mail) and use that instead.

Other sitesNote

Email accounts and passwords are per-site encrypted secrets — they are not carried in the application image. The production site must be configured separately the same way.

What do I actually fill in?

For a normal customer order:

You fill in

  • Company (Klemco India) & Customer
  • Items — code, qty, delivery date
  • Set Source Warehouse — usually Finished Goods
  • Plant Order Type (One-Shot) + any delivery notes / 3PL
  • Customer PO / Test Certs / Client Order Confirmation, if required

The system handles

  • Series, Totals, Grand Total — computed automatically
  • Tax — In-State / Out-State picked from plant vs delivery state
  • Status & the % Delivered / Billed / Picked meters
  • Discount Approval, Credit Control, Rate Contract flag
  • Commission, Sales Team, Auto Repeat, UTM — only if you use them
